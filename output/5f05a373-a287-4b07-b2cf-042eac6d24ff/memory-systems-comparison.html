设计思路对比

HY Memory 插件优先 · 渐进演化

  • 定位：OpenClaw 生态的记忆插件，非独立产品
  • 核心理念：记忆是 Agent 的附属能力，随 Agent 生命周期存在
  • 提取策略：ADD-only 单次提取，不做 UPDATE/DELETE，记忆只增不减
  • 演化机制：Evolution Chain — 新旧记忆形成链条，而非覆盖
  • 召回策略：Multi-layer Recall，分层召回（语义 + 时间衰减推测）
  • 隔离模型：User → Agent → Session 三级硬隔离
  • 部署哲学：autoStartServer 一键启动，开发者零运维负担
  • 局限：无图结构、无显式时序建模、无事实矛盾检测

Mem0 规模优先 · 信号融合

  • 定位：Universal Memory Layer，跨框架跨平台的记忆基础设施
  • 核心理念：记忆应该是独立于 Agent 的基础设施层
  • 提取策略：v3 新算法 — Single-pass ADD-only，一次 LLM 调用搞定
  • 关联机制：Entity Linking — 抽取实体并跨记忆关联，提升召回精度
  • 召回策略：三信号并行融合 — Semantic + BM25 + Entity Matching
  • 时序感知：Temporal Reasoning — 时间感知排序，区分过去/现在/未来
  • 部署哲学：三种形态渐进 — Library → Self-hosted → Cloud
  • 特色：Agent Signup 5秒注册、CLI、Browser Extension

Graphiti 图谱优先 · 时间建模

  • 定位：Temporal Context Graph Engine，不只是记忆而是知识图谱
  • 核心理念：事实有时效性，旧事实被取代而非被删除
  • 提取策略：Episode → Entity → Fact 三级增量抽取
  • 关联机制：原生图结构 — 实体间显式边关系，非扁平向量
  • 召回策略：Semantic + BM25 + Graph Traversal + Cross-Encoder Rerank
  • 时序建模：Bi-temporal — valid_at / invalid_at 显式时间窗口
  • 本体论：Prescribed (Pydantic 定义) + Learned (自动涌现)
  • 溯源：Episode 全链路溯源，每个事实可追溯到原始输入

选型建议

何时选择哪个？

选 HY Memory：你已经在 OpenClaw 生态里，需要一个开箱即用的记忆插件，不想运维额外基础设施。适合快速原型和个人 Agent 场景。代价是缺乏图结构和显式时序建模。

选 Mem0：你需要跨框架、跨平台的通用记忆层，追求生产就绪和规模扩展。三种部署形态让你从开发到生产无缝迁移。v3 新算法在基准测试中表现优异。适合需要快速集成、不想管图数据库的团队。

选 Graphiti：你的场景需要理解实体间的关系、事实的时间演变、矛盾检测和全链路溯源。典型场景：法律合规追踪、医疗病历演变、金融风控图谱。代价是需要运维图数据库（Neo4j/FalkorDB），整体复杂度最高。
