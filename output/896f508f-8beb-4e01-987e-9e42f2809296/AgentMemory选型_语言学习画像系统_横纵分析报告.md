# Agent Memory 选型：为语言学习者画像的持久记忆系统

> 研究时间：2026年6月 | 所属领域：AI 基础设施 / Agent 记忆系统 | 研究对象类型：技术选型（概念+产品）

## 一、一句话定义

这个系统要做的事不是「记对话」，而是**持续沉淀一个学习者的语言能力画像**——知道他已经掌握什么、在哪里反复卡壳、词汇增长曲线长什么样、哪个句式练了三次还是错——然后用这份画像反过来指导每日学习卡片的内容生成和难度选择。这在 Agent Memory 领域没有一个现成的、开箱即用的产品能直接搞定，但有三条技术路线可以组合出最佳答案。

---

## 二、需求拆解：这个记忆系统到底要「记住」什么

在跳进具体的框架对比之前，得先把需求拆透。笼统地说「要了解学习者的水平」不够，必须精确到需要什么类型的记忆、什么颗粒度、什么频率。

### 2.1 记忆的四个维度

按语言学习的真实需求，这个 Agent 记忆系统需要记住四个维度的东西：

**维度一：能力画像（静态+慢变）**
这是学习者的「身份证」。包括当前 CEFR 大概级别、听说读写四维的强弱分布、已知词汇量估算、发音弱项（哪个音总发不对）、偏好学习方式（喜欢看剧多于刷卡片、还是反过来）、每天能投入多长时间。这类信息更新频率极低——可能一个月才需要校准一次，但它决定了所有卡片内容的难度锚点。

**维度二：词汇与句式掌握矩阵（高频更新）**
这是整张记忆表的「血肉」。每一个被引入 SRS 卡片的词/句式/短语，都需要一条记录：它是什么时候引入的、复习正确率、最近一次正确/错误的日期、在 FSRS 中的难度参数（D）、是「刚学」「在巩固」还是「已掌握」。这些数据是每天生成新卡片时「该选什么难度」的决策依据。

**维度三：错误日志与弱项图谱（高频更新+跨会话关联）**
学习者在跟 AI 陪练或真人对话中犯的每一个被捕捉到的错误——比如时态混用、介词选错、某个发音总被纠正——需要被持久记录并按语言学类别归档。更关键的是，系统需要能识别「这个错误跟两个星期前那个是不是同一个根因」。比如他今天把「I go yesterday」说错了，系统应该能把它关联到上次他卡在「when I was young」的时态混用上。

**维度四：学习曲线与时序事件（中频更新）**
按日/周/月的粒度记录：每天学了多少分钟、产出了多少新卡片、复习正确率波动、连续打卡天数、哪个周进步最快、哪个周出现了平台期。这是用来做「学习日报」和激励反馈的，也是给老师/用户提供可量化进展的证据。

### 2.2 关键约束

不是所有记忆都要靠外部系统。根据我们的整体架构（每日 AI 学习卡片工作流），以下记忆类型已经有落点：

- **卡片级别的复习状态**——FSRS 算法已经管了，每张卡片的 difficulty/stability/间隔都是 FSRS 自己算的。不需要 Agent Memory 来管。
- **正在进行的对话上下文**——LLM 的 context window 或 session 级临时存储就够了。

真正需要 Agent Memory 来管的，是**跨会话的、需要检索和关联的、需要随时间演化的长期画像**。具体来说，是上述四个维度里那些「不是具体哪张卡片，而是关于这个人本身的、会持续变化的元知识」。

## 三、主流 Agent Memory 框架横评

2026 年的 Agent Memory 赛道已经不再是「有没有」的问题，而是「选哪个」的问题。我们从 5 个候选者里逐一过，回答三个问题：它怎么存、怎么查、适不适合我们的四维需求。

> 下文评测中引用的 LoCoMo 基准（Long-Context Memory Benchmark）是目前最主流的 Agent Memory 评测集，包含 81 个跨会话 QA 对，覆盖单跳、时序、多跳等类型。

### 3.1 Mem0：最流行，但只合适「偏好」不适合「画像」

Mem0 是 2024 年中发布的，是目前这个赛道下载量最大的方案。它的核心架构是**向量数据库 + 图数据库**双存储：向量库做语义检索，图库做实体关系网络。API 极简——`client.add("用户喜欢Python", user_id="alice")`——5 分钟就能接上。

优点很实在：接入成本是所有方案里最低的，有动态记忆压缩（相似条目自动合并），时间衰减加权（新记忆在检索时权重更高），而且对冲突信息（「昨天说喜欢 A，今天说喜欢 B」）有内置的矛盾解决机制。

但它的致命伤也很明确。首先，它的记忆本质是**扁平事实存储**——「用户喜欢 Python」「用户不喜欢 Java」这样的原子事实。对简单偏好类记忆足够，对需要层次化、需要时间演化的「画像」不够。其次，在 LoCoMo 基准的长对话测试中，Mem0 的准确率只有 66.9%（3 轮对话）到 68.5%（10 轮），对时序问题的处理能力偏弱——「他上个月那个时态错误后来改过来了吗」这类问题基本答不上来。

在 LoCoMo 基准测试中，每次对话的 token 占用约 7,000，延迟始终在 1.5 秒以下——效率表现不错，但精度不够高。

**对我们的适配度：「能力画像」这个维度可以勉强凑合用，但「错误日志关联」「学习曲线」基本不行。** 它可以用作轻量版的快速起步，但如果你的系统以后要深度理解学习者，Mem0 会是第一个被换掉的模块。

### 3.2 Zep：情节记忆好，但对超长周期支持有限

Zep 比 Mem0 进了一步——它把记忆组织成**情节图谱**（episodic knowledge graph），能感知事件的时间顺序。底层用的图引擎叫 Graphiti，专门处理动态知识图谱的更新和边失效（当你昨天说「不会虚拟语气」今天又能用了，系统会标记旧事实失效而非覆盖）。

在时序推理上优于 Mem0。它的 LoCoMo 基准第三方对比结果约 78.94%，明显高于 Mem0 的 66.9%。情节图谱的设计让它能回答「用户什么时候开始学现在完成时的」这类中等时间跨度的问题。社区活跃，文档完善，SDK 覆盖 Python/TypeScript/Go。

但 Zep 的局限在于：它对**跨月、跨季度的超长周期记忆**支持有限——更适合「周~月」的粒度。而语言学习是一个以月甚至以年为单位的过程，Zep 的情节图谱随着时间拉长，精度会衰减。另外，它的**用户画像自动归纳能力**较弱——你需要自己写提取画像的逻辑，Zep 只提供存储和检索。

**对我们的适配度：在词汇掌握矩阵和错误日志的「双周关联」上表现不错，但对维度四（月级以上学习曲线）有点不够用。** 适合作为短期到中期的数据存储层，但上面需要加一层画像归纳逻辑。

### 3.3 LangMem：LangChain 亲儿子，生态决定它

LangMem 是 LangChain 团队出的记忆管理方案。它的设计哲学是把记忆分为工作记忆（当前会话内）和长期存储（跨会话），核心是命名空间隔离和与 LangGraph Agent 的深度集成。

优点在于如果你全栈用 LangChain/LangGraph，它几乎是零摩擦接入。缺点也在于此——**强绑定 LangChain 生态**，如果你不用这套技术栈，接入代价就很高。它的时序记忆能力不如 Zep 和 TiMem。

LoCoMo 基准约为 78.05%（第三方评测）。在速度和延迟方面表现较慢。

**对我们的适配度：除非整个学习卡片系统的 Agent 层已经定下来用 LangGraph，否则不推荐。** 在我们的架构里（自建的 Python 工作流 + 轻量前端），LangMem 的生态依赖会是一个不必要的负担。

### 3.4 Letta（原 MemGPT）：自管理记忆的 Agent，太重了

Letta 的前身是 MemGPT，它的核心创新是用「操作系统虚拟内存」的比喻来做记忆管理——把 LLM 的上下文窗口当成 RAM，把外部存储当成硬盘，Agent 自己决定什么时候把什么数据从硬盘换进 RAM。

这个设计在需要 Agent 自主管理复杂记忆的场景（比如长篇小说创作、多日任务编排）里非常强大。但对我们的需求来说，它**太重了**。我们的记忆需求本质上是结构化的——能力画像、词汇表、错误日志、学习曲线——都是有明确 schema 的，不需要 Agent 自己来判断「应该记住什么」。Letta 的自主管理能力在这里是多余的，且引入了不可控的额外延迟和复杂度。

在 LoCoMo 基准中，Letta 的表现波动很大（3 轮 74%，10 轮 48-74%），说明它对长对话的稳定性不足。

**对我们的适配度：不适合。** 架构过重，我们的需求不需要操作系统级别的记忆自主管理。

### 3.5 TiMem：时序记忆树——为长期陪伴型场景而生的

TiMem 是 2025-2026 年新冒出来的方案，设计思路直接来自认知科学的**互补学习系统理论**（Complementary Learning Systems，CLS），模拟人脑的记忆巩固过程。

它的核心是**时序记忆树**（Temporal Memory Tree, TMT），五层结构：

1. **L1 原始对话片段**——最细粒度，精确到每条消息
2. **L2 会话摘要**——单次对话维度
3. **L3 每日总结**——日维度
4. **L4 每周总结**——周维度
5. **L5 人物画像**——全生命周期

查询时根据问题复杂度自适应选层——「今天学了什么」查 L3，「这两个月这个句式掌握了没有」查 L5。最关键的是，TiMem 不是简单地分五层独立存储，而是**层与层之间有语义链接**，能让你从一张卡片追溯到当时的上下文、当时的错误、当时的场景。

基准表现亮眼：LongMemEval-S 达到 76.88%，token 消耗减少 52.20%（相比不加记忆层）、LoCoMo 基准约 75.30%。这意味着长期运行成本显著低于 Mem0/Zep。

**对我们的适配度：是五个方案里最贴近我们需求的一个。** 它的五层时序树天然对应了我们的四个记忆维度——L2-L3 对应每日学习数据，L4 对应学习曲线周报，L5 对应能力画像，L1 提供回溯到原始上下文的能力（这对于场景回忆锚极其关键）。缺点是新项目，社区比 Mem0/Zep 小，文档还在完善中。

### 3.6 横轴小结

| 框架 | 架构 | 时序能力 | 画像归纳 | 接入成本 | 长期精度 | 适合 |
|------|------|---------|---------|---------|---------|------|
| Mem0 | 向量+图 | ⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐ | 轻量偏好 |
| Zep | 情节图谱 | ⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ | 中等周期 |

## 四、横纵交汇：最优方案不是「选一个」，是「分层组合」

看到这里，有一个判断已经非常清楚了。

**没有任何一个现成的框架能完整覆盖语言学习者的四维画像需求。** 但这不是坏消息——因为这个赛道的每个框架都不是面面俱到的通用方案，而是各有所长的模块。正确的做法是把它们当积木。

### 4.1 记忆系统的「三角组合」

我推荐的组合方案是：

```
TiMem（长期画像层）
    ↓
Zep（中周期事件 + 情节图谱）
    ↓
FSRS（卡片级算法层，已有）
```

- **最底层是 FSRS**：管每一张具体卡片的复习调度。这块我们已经有了，不需要动。
- **中间层是 Zep**：管「情节」——每次跟 AI/真人对话发生了什么、谁纠正了哪个错误、哪天你突然能把那个练了三周的句子说顺了。Zep 的情节图谱能做到「这个错误是三周前在提到 past perfect 的对话中第一次出现的」，这是时序关联。
- **最上层是 TiMem**：管「画像」——上面 Zep 积累的情节会被 TiMem 按时序记忆树自动归纳为 L4（每周总结）和 L5（学习者全局画像）。这些画像再被喂回 AI 卡片生成系统，作为提示词的一部分——「这个学习者在时态上连续三周准确率不到 60%，今天的每天卡片重点提示词里要增加时态维度的比重」。

### 4.2 为什么不选 TiMem 一个打全部

TiMem 的理论上限最高，但它是个新项目。Zep 的社区和文档成熟度可以让中间情节层更快落地。两者的分工很清晰——Zep 负责「记住发生了什么」，TiMem 负责「这个人的画像在时间轴上怎么变」。这种分层还有一个好处：如果 TiMem 后续更新或更换，只需要换顶层，中间情节层不动。

如果你追求极简化、愿意接受一些早期项目的风险，也可以只用 TiMem 一层。它的五层树本身已经覆盖了从原始对话到全局画像的完整链条。

### 4.3 记忆沉淀需要一个「测验层」

这套记忆系统光有存储还不够。需求里说的「通过各种方式的测验来沉淀记忆」，本质上是**知识追踪**（Knowledge Tracing）问题。

知识追踪在教育技术领域有两条成熟的技术路线：

- **贝叶斯知识追踪**（BKT）：用概率模型（隐马尔可夫模型）来推断学生对每个知识点的掌握状态。输入是学生的答题对错序列，输出是对每个知识点「已掌握」的概率估计。它的核心参数是四个概率——初始掌握、学习率、猜测率、失误率。BKT 的优点是可解释性强、模型轻量，每个知识点的掌握概率一目了然。

- **深度知识追踪**（DKT）：用 RNN/Transformer 建模学生答题序列，捕捉不同知识点之间的隐藏依赖关系。比 BKT 更准，但需要大量训练数据，且缺乏可解释性。

在我们的场景里，**推荐 BKT 作为轻量启动**。原因很直接——我们的知识点（词汇、句式、短语）每个都有明确的「对/错」反馈（SRS 卡片答对/答错、AI 陪练有没有卡壳），数据格式天然适配 BKT 的输入。而且 BKT 的输出可以直接作为 TiMem 画像层的输入：「时态类句式·掌握概率 42%，建议增加复习密度」。

如果要做到「主动测验」，可以在每次 SRS 复习里混入少量自适应测验题——不光是让你回忆卡片正反面，而是让你在模拟对话场景里用这个词造一个句子，系统根据你的表现更新 BKT 参数。这部分逻辑可以内置在每日卡片生成提示词里，让 AI 自动判断哪类卡片需要额外的场景造句测试。

### 4.4 最终架构图

把前面三份报告串起来，整个学习者系统的终态是：

```
┌──────────────────────────────────────────┐
│         每日学习（影子跟读/输入/对话）        │
└──────────────┬───────────────────────────┘
               │ 当日材料
               ▼
┌──────────────────────────────────────────┐
│   AI 卡片生成引擎（GPT-4o + 提示词）         │
│   ← 接收 TiMem 画像（作为难度和重点锚点）      │
│   → 输出 5-10 张多维卡片 + 学习日报          │
└──────────────┬───────────────────────────┘
               │
      ┌────────┼────────┐
      ▼        ▼        ▼
  FSRS SRS   Zep情节  TiMem画像
  (卡片复习) (错误日志) (能力画像+学习曲线)
      │        │        │
      └────────┼────────┘
               ▼
         BKT 知识追踪
      (掌握度概率估计)
               │
               ▼
         反馈到卡片生成引擎
      (调整难度、重点维度、测验强度)
```

每一层各司其职，没有重复，没有空位。

### 4.5 三个剧本

**最可能的剧本。** 先用 TiMem 单层 + FSRS 跑起来。TiMem 的五层时序树天然覆盖了从中周期到长周期的全部记忆需求，Zep 可以后续再加。关键是在系统跑起来的两周内，需要手动校准初始画像——让他做一次自评（「你觉得自己现在听说在什么水平」）、导入他已有的 SRS 卡片数据（如果有）。前三个月的画像准确度会有波动，但每一次他完成当天的卡片复习、每一次他在 AI 对话中卡壳并被记录，图像就会更清晰一层。

**最危险的剧本。** 在选型上投入太多时间，在没有实际数据的情况下反复比较框架、设计「完美的画像 schema」。记忆系统的好坏，框架只占三成，数据的质量和一致性占七成。最早两周最容易踩的坑是「记录太细导致画像膨胀」——比如把每次对话的每个错误都全量存储，但从不归纳。TiMem 的五层设计恰好是防这个的：L2 → L3 → L4 → L5 的逐层归纳会自动压缩，但你得让系统真的跑起来才有这些压缩。

**最乐观的剧本。** TiMem + FSRS + 轻量 BKT 三件套跑通后，三个月的画像已经足够精确到能指导卡片生成的难度控制。半年后，系统能告诉你「你在过去六个月里学会了 427 个主动词汇，口语句式正确率从 48% 提升到 71%，目前最大的弱项是时态一致性，过去四周的练习已经在改善但这个维度还需要额外关注」。每次跟 AI 陪练聊天，系统因为知道你的当前弱项，会主动选择包含你弱项句式的对话场景。学习者不再需要「计划」学什么——系统替你想好了，你只需要出现、开口。
